# Ch-Bot — ครูเอสคิว (ผู้เชี่ยวชาญ SQL)

แชตบอทฐานข้อมูลและ SQL ตอบภาษาไทย โดยดึงคำตอบจากตำรา
**การจัดการระบบฐานข้อมูลเพื่องานธุรกิจ** (ฐาปนี เพ็งสุข, ม.ราชภัฏอุดรธานี, 2562) 426 หน้า
ที่แปลงเป็น [`knowledge/db_business_textbook_th.md`](knowledge/db_business_textbook_th.md) เท่านั้น ไม่ใช้ AI แต่งคำตอบ
ใช้งานผ่านหน้าเว็บ (ระบบ LINE และ Telegram ถูกเอาออกแล้ว)

> โปรเจกต์นี้เป็น **Python / Flask** ไม่ใช่ Node.js — ใช้ `npm start` ไม่ได้ครับ

## วิธีรัน

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
./venv/bin/python app.py
```

แล้วเปิดเบราว์เซอร์ที่ http://127.0.0.1:5001 — ไม่ต้องใช้ API key ก็ตอบได้

ถ้าใส่ `ANTHROPIC_API_KEY` (Claude) หรือ `GEMINI_API_KEY` (Gemini) ในไฟล์ `.env` บอทจะให้ AI ช่วยตีความคำถามที่พิมพ์เอง
ดูหัวข้อ "AI ช่วยเลือกหัวข้อ" ด้านล่าง

| `templates/index.html` | หน้าเว็บแชต |
| `static/figures/` | รูปประกอบ 126 รูป ตัดจากหน้า PDF (checksum อยู่ใน manifest) |
| `data/` | สำเนาประวัติแชตเว็บฝั่งเซิร์ฟเวอร์เป็นไฟล์ JSON (ไม่ขึ้น git) |

## วิธีตอบ

บอทเลือกหัวข้อที่ตรงกับคำถาม แล้วแสดงเนื้อหาจากตำราตรง ๆ ไม่ย่อ ไม่สรุป ไม่เติมคำ (รวมคำสั่ง SQL ในเล่ม)
ตอบหัวข้อเดียว เว้นแต่คำถามถามหลายเรื่อง (เช่น "INNER JOIN กับ LEFT JOIN") จึงตอบหัวข้อละเรื่อง สูงสุด 3 หัวข้อ

### ตอบเฉพาะส่วนที่ถาม

ถามด้วยชื่อหัวข้อหรือเลขหัวข้อ (เช่น "ชนิดของแฟ้มข้อมูล", "7.5") ได้ทั้งหัวข้อ
แต่ถามเรื่องเดียวในหัวข้อยาว (ยาวเกิน 1,500 ตัวอักษร) จะได้เฉพาะย่อหน้าที่ตอบเรื่องนั้น พร้อมตัวอย่าง รูป ตาราง และโค้ดที่ประกอบ
- "สารสนเทศคืออะไร" → เฉพาะความหมายของสารสนเทศในหัวข้อ 1.1 (ไม่รวมความหมายของข้อมูลและรูป 1.3)
- "ทูเพิลคืออะไร" "DDL คืออะไร" "ฟิลด์คืออะไร" → ศัพท์ที่ตำรานิยามไว้ในเนื้อหา (ไม่ใช่ชื่อหัวข้อ) ก็หาเจอ
- "ข้อดีของแบบจำลองฐานข้อมูลเชิงสัมพันธ์" "COUNT ใช้ยังไง" → เฉพาะหัวเรื่องย่อยนั้นในหัวข้อ 4.3 / 9.10.3

คำตอบบางส่วนมีบรรทัด "แสดงเฉพาะส่วนที่ตอบคำถาม แตะเพื่ออ่านทั้งหัวข้อ" กับปุ่มชื่อหัวข้อ
แตะปุ่มหรือพิมพ์ "อธิบายเพิ่ม" จะได้ทั้งหัวข้อ ข้อความที่แสดงยังเป็นบรรทัดจากไฟล์ตำราตรงตัวทุกบรรทัด

### AI ช่วยเลือกหัวข้อ (ไม่บังคับ)

คำถามที่คนพิมพ์เองอาจไม่มีคำตรงกับชื่อหัวข้อ เช่น "ชนิดข้อมูลใน SQL มีอะไรบ้าง" (ค้นจากคำอย่างเดียวได้ 8.6 INSERT INTO แทน 8.2)
ถ้าตั้ง API key ไว้ ระบบส่งคำถาม + รายชื่อหัวข้อ (และศัพท์/หัวเรื่องย่อยในแต่ละหัวข้อ) ให้ AI เลือกเลขหัวข้อ
แล้วส่งย่อหน้าของหัวข้อนั้น (มีเลขกำกับ) ให้เลือกเลขย่อหน้า **AI ตอบกลับได้แค่เลข** ระบบตรวจว่าเลขมีอยู่จริง
แล้วนำข้อความจากตำรามาแสดงเอง AI จึงเติมคำหรือแต่งคำตอบไม่ได้
- ถามด้วยชื่อ/เลขหัวข้อ ศัพท์ที่ตำรานิยามไว้ หรือหัวเรื่องย่อยตรงตัว ระบบตอบเองได้แน่นอน ไม่เรียก AI
- คำถามที่ถามซ้ำ (เช่นทั้งห้องถาม "SQL คืออะไร") ใช้ผลเดิม ไม่เรียก AI ซ้ำ
- ถ้าโควตาเต็ม เน็ตหลุด หรือ AI บอกว่าไม่เจอ ระบบตอบด้วยวิธีค้นแบบเดิมทันที ผู้ใช้ไม่เห็น error

| ตั้งค่าใน `.env` | ผล |
|---|---|
| `ANTHROPIC_API_KEY=...` | ใช้ Claude (ค่าเริ่มต้น `claude-sonnet-5` เปลี่ยนได้ด้วย `ANTHROPIC_MODEL` เช่น `claude-sonnet-5-5`, `claude-haiku-4-5`) — เสียเงินตามจำนวนโทเคน |
| `GEMINI_API_KEY=...` | ใช้ Gemini (ค่าเริ่มต้น `gemini-3.5-flash-lite`, `GEMINI_MODEL`) — โควตาฟรี 15 ครั้ง/นาที คำถามหนึ่งข้อใช้ 1–2 ครั้ง |
| มีทั้งสอง | ใช้ Claude, บังคับได้ด้วย `AI_PROVIDER=gemini` |

### ถามซ้ำได้คำตอบเดิมเสมอ

AI ตอบไม่เหมือนเดิมทุกครั้ง (Gemini แม้ตั้ง temperature 0 ก็ยังต่าง, Claude Sonnet 5 ตั้ง temperature ไม่ได้เลย)
จึงจำคำตอบแรกของคำถามที่ต้องตีความไว้ใน `ai_answers.json` แล้วใช้ซ้ำ ไม่ถาม AI ซ้ำ
- คำถามที่พิมพ์ต่างกันเล็กน้อยถือเป็นข้อเดียวกัน: "SQL คืออะไร" = "sql คืออะไรครับ?" = "sql  คือ อะไร"
- คำถามที่ระบบค้นเองได้แน่นอน (ชื่อหัวข้อ, ศัพท์ที่ตำรานิยามไว้) ได้ผลเดิมทุกครั้งอยู่แล้ว ไม่ต้องจำ
- ตอนที่ AI ใช้ไม่ได้แล้วตอบด้วยวิธีค้นเอง ก็จำคำตอบนั้นไว้เช่นกัน (คำตอบไม่เปลี่ยนเองเมื่อ AI กลับมา)
- คำตอบเปลี่ยนได้เฉพาะเมื่อแก้ตำรา (checksum เปลี่ยน คำตอบที่จำไว้ใช้ไม่ได้) หรือผู้ดูแลลบรายการใน `ai_answers.json`
  หรือสร้างใหม่ทั้งหมดด้วย `eval_questions.py --ai --pin --fresh`
- รันในเครื่อง: คำถามใหม่ถูกบันทึกลงไฟล์ **บน Vercel ไฟล์อ่านอย่างเดียว** และเครื่องแต่ละตัวไม่มีที่เก็บร่วมกัน
  เว็บจึงใช้เฉพาะคำตอบที่ commit ขึ้นไป คำถามใหม่ที่ไม่มีในไฟล์ตอบด้วยวิธีค้นเอง (ได้ผลเดิมทุกครั้ง) ไม่เรียก AI สด
หัวข้อที่แค่มีคำซ้ำกับคำถามแต่ไม่ได้ตอบส่วนที่ถาม จะไม่ถูกดึงมาปน
ท้ายทุกคำตอบบอกที่มา เช่น `แหล่งข้อมูล: ตำรา… · บทที่ 4 แบบจำลองฐานข้อมูลเชิงสัมพันธ์ · หน้า 69–70 (PDF หน้า 96–97)`
(เก็บไว้ในส่วน `### แหล่งอ้างอิง` ของแต่ละหัวข้อในไฟล์ความรู้)
ถ้าไม่มีหัวข้อในตำราที่ตรงกับคำถาม จะตอบว่า "ไม่มีข้อมูลเรื่องนี้ในตำราครับ"
ถ้าหัวข้อมีรูปประกอบ หน้าเว็บจะแสดงรูปเหนือคำบรรยาย "ภาพที่ X.Y" เหมือนในเล่ม กดที่รูปเพื่อดูขนาดใหญ่ได้
คำทักทาย คำขอบคุณ และ "ตอบอะไรได้บ้าง" ตอบด้วยข้อความคงที่ พร้อมรายชื่อบทจากไฟล์ความรู้
คำที่แค่โผล่ในเนื้อหา (เช่น Transaction ในตาราง) ไม่นับว่าตำราอธิบายเรื่องนั้น
บอทจึงไม่แต่งเนื้อหาเอง แต่ก็เขียน query ใหม่ตามโจทย์ให้ไม่ได้

หัวข้อคือหัวข้อย่อยตามสารบัญ (เช่น 4.5, 9.11) บวกบทนำ บทสรุป และแบบฝึกหัดของแต่ละบท
หัวข้อที่ยาวเกิน ~3,500 ตัวอักษรถูกแบ่งตามหัวข้อย่อยในเล่ม เช่น `4.5 ประเภทของคีย์ · 3. คีย์หลัก (Primary Key)`
ถามหัวข้อหลัก (เช่น "ประเภทของคีย์") ได้ครบทุกส่วน ถามเจาะจง (เช่น "คีย์หลัก") ได้เฉพาะส่วนนั้น
ถามด้วยเลขหัวข้อ (`7.5`) หรือบท (`แบบฝึกหัดบทที่ 7`) ได้

### ถามต่อจากเรื่องที่คุยอยู่

บอทจำเรื่องที่คุยอยู่จากคำตอบล่าสุดในประวัติแชต (เบราว์เซอร์ส่งประวัติมาทุกครั้ง) แล้วตอบจากตำราเช่นเดิม
- "ขอตัวอย่างเพิ่ม" / "ยกตัวอย่าง" → ตัวอย่างเรื่องนั้นจากหัวข้ออื่นในตำรา (คำสั่ง SQL ก่อน) ครั้งละ 3 ตัวอย่าง
  "มีอีกไหม" ได้ชุดถัดไปที่ยังไม่เคยแสดง ถ้าหมดจะบอกตรง ๆ
- "อธิบายเพิ่ม" ต่อจากคำตอบที่แสดงเฉพาะส่วน → ทั้งหัวข้อนั้น
- "อธิบายเพิ่ม" (ต่อจากคำตอบที่แสดงครบแล้ว) / "มีอะไรเพิ่มเติมที่เกี่ยวกับหัวข้อนี้" → หัวข้อที่เกี่ยวข้องเป็นปุ่ม แตะเพื่อดูเนื้อหา
- "มันต่างกันยังไง" → สองเรื่องล่าสุดที่คุย, "แล้วมันต่างจาก X ยังไง" → เรื่องที่คุยอยู่ + X
  คำถามใหม่ที่ระบุครบในตัว (เช่น "INNER JOIN กับ LEFT JOIN ต่างกันยังไง") ไม่เอาเรื่องเดิมมาปน

ก่อนตอบทุกครั้งระบบตรวจว่า MD และ PDF ตรงกับ `manifest.json` ถ้าไม่ตรงจะหยุดตอบ
ดังนั้นเวลาแก้เนื้อหา ต้องแก้ MD และ PDF ไปด้วยกัน แล้วอัปเดต checksum และ `topic_count` ใน manifest ด้วย

## ทดสอบ

```bash
./venv/bin/python -m unittest test_knowledge test_handbook_app test_dataset_only test_conversation test_focus -v
```

unittest ไม่ต่อเน็ต (ส่วนที่เรียก AI ใช้ตัวปลอม) ทดสอบกับ Gemini จริงด้วยชุดคำถาม:

```bash
./venv/bin/python eval_questions.py                   # ไม่ใช้ AI: ทุกหัวข้อตามสารบัญ + หัวเรื่องย่อย + คำถามพิมพ์เอง + นอกตำรา
./venv/bin/python eval_questions.py --ai              # ใช้ AI ตาม key ใน .env (ที่จำคำตอบชั่วคราว ไม่แตะ ai_answers.json)
./venv/bin/python eval_questions.py --ai --repeat 3   # + ถาม AI ซ้ำ 3 รอบโดยไม่จำคำตอบ นับข้อที่ AI ตอบไม่เหมือนเดิม
./venv/bin/python eval_questions.py --ai --pin        # บันทึกคำตอบลง ai_answers.json เพื่อ commit ขึ้นเว็บ (--fresh = ตอบใหม่หมด)
```

แต่ละข้อตรวจว่าได้หัวข้อที่ถูก มีข้อความที่ตอบคำถาม **ไม่มี**ข้อความของเรื่องอื่นในหัวข้อเดียวกัน (ตอบเกิน)
และถามซ้ำ (รวมแบบเติม "ครับ") ต้องได้คำตอบเดิมทุกตัวอักษร

## Deploy ขึ้น Vercel

Vercel ตรวจจับ Flask ให้อัตโนมัติ (entrypoint `app.py`, ตัวแปร `app`) — ไม่ต้องมี `vercel.json`

1. Import repo นี้ที่ https://vercel.com/new แล้ว Deploy ได้เลย
2. คำตอบจาก AI บนเว็บมาจาก `ai_answers.json` ที่ commit ขึ้นไป (เว็บไม่เรียก AI สด ดู "ถามซ้ำได้คำตอบเดิมเสมอ")
   จึงไม่ต้องตั้ง API key บน Vercel อยากให้เว็บรู้จักคำถามใหม่ ๆ: รันถามในเครื่อง (หรือ `eval_questions.py --ai --pin`)
   แล้ว commit `ai_answers.json` ขึ้นไป

### ข้อจำกัดบน Vercel

- **แชตหน้าเว็บ** เก็บประวัติไว้ใน `localStorage` ของเบราว์เซอร์ ไม่หายเมื่อรีเฟรช แต่ถ้าเปลี่ยนเครื่องหรือล้าง cache จะไม่เห็นแชทเก่า
- สำเนาแชตฝั่งเซิร์ฟเวอร์เขียนได้เฉพาะ `/tmp` จึงไม่ถาวร (หน้าเว็บไม่ได้ใช้สำเนานี้ จึงไม่กระทบการใช้งาน)
